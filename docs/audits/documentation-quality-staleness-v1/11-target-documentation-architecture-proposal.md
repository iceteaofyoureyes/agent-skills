# Target documentation architecture proposal

This is a proposed information architecture, not an implementation. It keeps machine-readable contracts authoritative and gives operators one path from role to task to result/recovery.

## Navigation principles

1. One canonical explanation per concept; role/task pages link to it.
2. Every current page shows suite/Kit version context or links to the machine manifest.
3. Each task guide names prerequisites, inputs, owned outputs, gate owner, expected status, forbidden inference and next transition.
4. Human gates and TEST_ONLY boundaries are visible where the operator acts.
5. Current, compatibility and historical pages occupy separate routes.
6. VI remains the current primary language unless Human review chooses otherwise; current operator workflows get parity where release/operation needs it.
7. Package payload pages are identified before any move or edit so authority regeneration is planned.

No directories or documents were created or moved to this proposed architecture during the audit.
