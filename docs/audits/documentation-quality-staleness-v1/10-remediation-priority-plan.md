## Package ownership map for future waves

- Test package authority currently includes 194 managed entries. It includes kits/test/README.md; Test Automation and Execution guides in English/Vietnamese; Test VNext/legacy examples; all declared Test schemas, templates, runtime files and skill payloads. Changes to these inputs require generated authority and payload digest updates.
- Dev provenance binds the plugin payload and its runtime source closure. Changes to kits/dev/plugin skills/references, project-foundation/SKILL.md or bound runtime files require provenance regeneration and installed acceptance.
- BA installation copies ba-workflow and manifest-declared atomic skills. Changes to those skill bytes require BA package/install acceptance; BA has no Test-style package-authority file in the current manifest.
- Standalone docs under docs/ are generally outside the installed package unless they are explicitly selected by a kit manifest.

## Wave dependencies

Wave A must settle the package byte policy before Wave D describes package recovery. Wave B should precede Wave C so role/task guides have stable homes. Wave E can run independently but must preserve evidence and package-relative paths. Wave F follows agreed IA and terminologies. Any change to machine contracts, schemas, runtime behavior, authority, package versions or hashes is outside this audit and needs its own authorized implementation scope.
