# Technical approval V2 receipt boundary

This file is documentation, not a receipt. It does not approve a change.

The host system must authenticate a real Human or Tech Lead and bind that
receipt to the exact technical snapshot, Engineering Impact, ED set, plan,
tasks, repository bases, write scopes, and risk. Requests, local files, workflow
choices, examples, and this boundary document cannot authenticate approval.

The executable contract is `schemas/technical-approval-v2.schema.json`.
Create a receipt only through the trusted host after the person reviews the
exact snapshot. Do not fill an example actor, timestamp, decision, or digest and
present it as approval.
